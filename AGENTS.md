# Google Flow production workspace

Codex is the producer. Generate media only in the user's signed-in **Microsoft Edge Google Flow session**, through the registered `flow-connector` MCP tools. If unavailable, use the installed `flow-auto` CLI through normal host approvals. Preserve the two existing reference/guidance folders.

## Four chat entry points

- **Plan a video about …**: inventory supplied assets; create `projects/<slug>/`; write the brief, continuity sheet, shot/asset plan, edit list and manifest. Run `python flow.py validate <project>` and `dry-run`. Do not generate.
- **Produce this video …**: plan, record the request as authorization and its image/video caps, then execute one ready unit at a time through review and delivery. This request authorizes production within the stated limits; do not ask for another blanket confirmation.
- **Revise shot S03 …**: use `revise` to create a new take, preserving previous takes and selections. Change the smallest relevant input. Review and select it; report downstream units flagged stale. Respect the existing cap.
- **Resume project …**: reconcile saved submissions with real jobs and downloads before any generation. Poll known jobs; leave ambiguous submissions pending. Then continue ready work. Never use the CLI's generic `generate resume` for this workflow.

Read [README.md](README.md), [docs/PRODUCTION.md](docs/PRODUCTION.md), [docs/CAPABILITIES.md](docs/CAPABILITIES.md), and [docs/LESSONS_LEARNED.md](docs/LESSONS_LEARNED.md) before production. For dialogue use [docs/VIDEO_RECIPE.md](docs/VIDEO_RECIPE.md) and the optional `dialogue` contract in `templates/dialogue-shot.json`. The runner manages state; Codex supplies the creative plan, calls MCP, and inspects media.

## Non-negotiable execution rules

1. Extract audience, purpose, platform, ratio, runtime, style, subject, beats, audio, supplied assets and caps. Infer reversible details and record them. Ask one focused question only when the answer materially changes the film or requires additional spending.
2. Separate edit seconds from generated seconds. Verify current model/mode constraints. Use explicit `flow-*` modes, model, ratio, output count and supported duration; set CLI resolution or verify it in Edge for MCP. Unprefixed CLI modes target Grok. Quote no unverified credit prices.
3. Record one Flow project URL/ID per film and reuse it. Before each submission check `flow_status({site:"flow"})` (or CLI equivalent) AND verify the correct signed-in project is visible in Edge, resolution is set, and the free-plan side panel remains open. Status alone does not prove project identity or tab visibility. Use `preflight-check` to anticipate expiry; renew from actual UI observations autonomously when available. If UI access is unavailable, bundle factual setup confirmation with an already-needed playback review. Never extend the 15-minute limit from status alone or recycle an old observation as fresh evidence.
4. Essential references must be visually reviewed and selected before dependent clips. Give references distinct roles. Record exact source take and timestamp for extracted frames. Generate dependent units in order; inspect the first look-establishing take before continuing.
5. **Journal before sending**: `prepare --transport mcp` saves an immutable request and marks the take `submission_pending`. Read it with `python flow.py payload PROJECT TAKE` and parse the ASCII-escaped JSON; never rebuild prompts through shell output or copy only part of the request. Call `flow_generate` exactly once with that payload. Immediately save the tool response and use `record`. Poll with `flow_get_job`; never repeat `flow_generate` for a pending take. Preserve automatic approval rejections separately; do not treat them as Flow failures or bypass a rejected action. For CLI fallback use `run-cli`, which follows the same protocol.
6. A crash after acceptance but before receiving the ID is ambiguous. Use `flow_list_jobs` and downloads; see resume rules in PRODUCTION.md. An empty/truncated job list is not proof of non-submission. Do not clear pending state or create another take to bypass it.
7. Preserve raw responses, exact prompts, references, settings, job IDs, original download paths, previous takes and selected outputs. Verify files with `probe`, then inspect opening/action/ending, identity, motion, continuity and sound where available; record concrete review evidence with `review`. Never label an uninspected file verified.
8. At disconnection/stall preserve state and ask the user to open Flow in Edge, sign in, enable Flow Connector, keep the tab/window and side panel visible, then confirm before rechecking. Relay specific access instructions, returned reset times or upgrade links exactly. Cooldowns are expected; wait/poll without duplicate submissions. Stop at account/project caps; do not upgrade or buy credits.
9. Deliver selected take IDs and actual file links in edit order, trim points, verified duration and remaining manual checks. Assemble only when requested; `assemble` uses the installed FFmpeg and checks the result. Do not claim a finished export before verifying it.
10. **One speaker owns the whole turn, including the first word.** For dialogue, give each video unit the structured `dialogue` contract. Identify speaker/listeners by stable IDs and visible position/clothing. Default to 0.4 s opening silence and 0.6 s final settling within the clip. Both mouths are closed at shared boundary images; listeners never start a word, lip-sync, or prepare to reply before the next clip. Inspect/listen to the first 1–2 seconds, complete line and last second. A first word spoken by the listener fails selection; record explicit `dialogue_checks` from real agent/user playback. These prompt cues are a proposed mitigation, not a proven guarantee.
11. A connector-reported failure does **not** prove that no Flow asset exists. Before retrying, requesting a cap increase, dropping a shot or shortening the film, check known jobs, exact download folders and visible project assets. Use `recover` for an existing manually downloaded clip with project/source evidence; preserve failed responses and an unknown queue-job ID honestly. Recovery adds zero generation outputs and cannot clear a different ambiguous submission.
12. Use `probe --fit-shortfall` for a small nominal-duration shortfall (at most 0.15 s). This journals only the editorial endpoint and total edit length; raw files, requests and settings stay unchanged. Never remove a spoken word, pad a large shortfall or claim a smooth join from matching stills.
13. At intake, record project folder, download location, caps including revisions, and whether the user wants an assembled film. Reuse that authorization without asking again. Do not ask for low-impact creative choices or routine permission already covered by the brief. Human playback is needed only for checks the agent cannot actually perform; check the first speaking take of each character, then group independent remaining clips for review when appropriate.

The initial acceptance run was **dry-run only**; `tests/fixtures/ceramicist-plan.json` is the frozen test baseline. Live project folders may now contain real takes and authorizations: read their current state and never reset them from an example. Run `python -m unittest discover -s tests -v` for zero-Flow-generation acceptance tests.
